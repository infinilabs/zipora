## 5. `E1.1` (G15) — Systemic End-to-End Search Benchmark (`make bench_e2e_search`, `8a1b92e`)

### 5.1 Architecture (`benches/e2e_search_bench.rs`)
- **Corpus & Queries** (`8a1b92e:benches/e2e_search_bench.rs:411-607`, fixed seed `0x5A17_0E11_E2E5_EA2C`):
  - `20,000` documents (`doc_lens` in `32..=512`), `4,096` vocabulary terms (`687,888` total postings), and `10,000` Zipf queries (`2,500` each of `1_term`, `2_term`, `3_term`, and `4_term`).
- **Zipora Index & Block-Max WAND / MaxScore Engine** (`8a1b92e:benches/e2e_search_bench.rs:614-1264`):
  - Term dictionary: `DoubleArrayTrieMap<u32>` (`69,632` bytes for `4,096` terms).
  - Document length norms: `FieldnormEncoder` (`20,000` bytes = `1.00 B/doc`) + `FieldnormEncoder::build_norm_table`.
  - Per-term postings: `HybridPostingList::from_sorted` across all 5 encodings (`2,688` `Dense`, `1,024` `EliasFano`, `352` `Partitioned`, `24` `Optimal`, `8` `Clustered`; `979,528` bytes = **`1.424 B/posting`**) + 64-doc Block-Max metadata (`block_max_doc_ids: Vec<u32>` and `block_max_scores: Vec<f32>`).
  - Query evaluation (`search_bmw`, `search_single_term`, `search_multi_term_bmw`):
    - Looks up query terms in `DoubleArrayTrieMap<u32>`.
    - Orders multi-term query terms by `max_term_score` descending and prunes non-essential terms and 64-doc blocks via Block-Max upper bounds (`lead_term.block_max_scores[blk_idx] + rem_upper <= cur_theta`).
    - Batch-scores surviving 64-doc lead blocks via `Bm25BatchScorer::batch_score_with_prefetch` and filters candidates in SIMD via `simd_block_filter`.
    - Advances trailing/earlier cursors across 64-doc blocks via `simd_gallop_to(&term.block_max_doc_ids, &mut blk, doc_id)` (checking block-max upper bounds before decoding!) and stateful `HybridCursor::advance_to_geq`.
- **Parity & Competitor Baseline** (`8a1b92e:benches/e2e_search_bench.rs:1270-1416`):
  - `Cargo.lock` is frozen under `--locked` in `make sanity` (`S21-R1`), so external `tantivy` crates are deferred to `E2`; `benches/e2e_search_bench.rs` compares against an in-process uncompressed inverted-index baseline (`HashMap<String, u32>` + uncompressed `Vec<u32>` doc IDs + `Vec<u16>` TFs = `6.000 B/posting` + full BM25 scan) on the identical corpus and 10,000 queries, and verifies `100.0%` top-10 recall and `< 1e-4` score parity before timing.
